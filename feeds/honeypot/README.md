# Honeypot indicators

Machine-generated by a small public honeypot (T-Pot + custom decoys), refreshed
every six hours. Free to use; no warranty, no attribution required.

| File | Contents |
|---|---|
| `hashes.txt` | SHA-256 of captured payloads, one per line, family name when known |
| `hassh.txt` | SSH client fingerprints (`hassh`) of observed bots |
| `wallets.txt` | crypto payout addresses from fake RPC endpoints |
| `iocs.csv` | everything, with first/last seen and counts |
| `iocs.stix.json` | the same as a STIX 2.1 bundle |
| `index.json` | generation time and counts, for change detection |

## Consume it

```sh
# hashes only, for an AV-ish blocklist
curl -fsS https://raw.githubusercontent.com/unerror/security/main/feeds/honeypot/hashes.txt

# CSV rows newer than a local copy
curl -fsS .../iocs.csv | awk -F, 'NR>1 && $5 >= "2026-10-28"'

# STIX into MISP / OpenCTI
curl -fsS .../iocs.stix.json -o bundle.json
```

## What is not here, and why

**No IP addresses.** A source IP is almost always a compromised camera, router or a
shared host with hundreds of other tenants. Publishing them harms victims and is
worthless within days. Report scanner IPs to the provider's abuse contact (RDAP) or
AbuseIPDB instead; that is where they belong.

Everything published here — file hashes, wallet addresses, SSH client fingerprints,
injected public keys — identifies the tooling, not a person, and stays true longer.

Presence in this feed is evidence of malicious activity on one honeypot. Absence
means nothing.
